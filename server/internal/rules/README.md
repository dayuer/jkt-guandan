# 规则引擎（Go）

纯逻辑，不读时间、不读随机数：同样的初始局面 + 同样的动作序列一定走到同样的局面（复盘、
断线恢复、随机对局都靠这条）。

| 文件 | 管什么 |
|---|---|
| `deck.go` | 牌、牌堆、牌面写法 |
| `power.go` | 牌力（打几的时候谁大） |
| `deal.go` | 洗牌、发牌（随机源从外面注入） |
| `combo.go` | 认牌型（`Recognize` / `Compare` / `Pick`），逢人配的顶法 |
| `moves.go` / `moves_gen.go` | 一手牌能打出去哪些（`Moves`：领出列全部、跟牌只列压得住的） |
| `play.go` | 出牌状态机（出牌、过牌、借风、出完顺序、局面存成 JSON 再读回） |
| `tribute.go` | 进贡、还贡、抗贡，接 `scoring` 算下一副打几 |
| `sim_test.go` | 随机对局（一副一副 + 跨多副整场），性质测试的驱动器 |
| `moves_old_test.go` | 老慢路径留成参照，守「优化之后行为一样」 |

牌例与两端的约定在 [`testdata/rules/README.md`](../../../testdata/rules/README.md)。

## 写性质测试之前，先问一句：这条期望值是从哪来的

性质测试（随机跑、和某个参照比）的坑一般不在实现，在**期望值本身**。下面几条都是真踩过的
（#204 第 4–7 步，auditor-240/242/246/251 的复审里被点出来的）：

1. **别拿被测实现自己的输出当期望值。** 「`Next` 等于 `scoring.Compute`」看着像交叉验证，
   其实 `Next` 就是包了 `Compute` —— 把 `Level` 改死它照样绿。要按规则**另推一份**再比
   （`simRule`：第二条 12 的 +3/+2/+1、封顶 A、第十二条的过 A 条件）。
2. **注意断言发生在什么时刻。** 「进贡前后牌数守恒」写在 `Hands()` 之前，查的就是刚发的牌，
   白查。要查的是**贡完还完**之后每一家的手牌，而且要**逐座**比。
3. **比整串，别比几个汇总数。** 「存过档 vs 没存过档」只比 7 个计数，撞巧一样的可能不小；
   要比每一副的账（含每一步动作），保证真能落在同一条路上。
4. **别只查「函数返回了错」。** 要查错误码（`errors.Is` 对哨兵）**和局面一个字都没变** ——
   不然「先把局面改了再报错」这类改法照样漏过去。
5. **每条规则要有真正拦得住它的用例。** 两条规则叠在一起时，常常是被另一条挡下来的：
   「红心级牌除外」在手里有 ♠A 时是被「贡最大的一张」挡住的；`holds` 那一段被 `canReturn`
   挡住（用例里那张牌恰好是上一行刚贡进去的）。要构造**只有这条规则能拦**的那个局面。
6. **随机语料抽不到的边界要写死**（`randomHand` 抽不到 A2345 这种窗口），参照实现要真的独立
   （`moves_old_test.go` 的老慢路径、`simModel` 的独立推算、`planTribute` 的规则推算）。

判据只有一条：**把对应的那几行改坏，这些测试会不会红、而且是不是「对的那条」红。**
不会红的性质等于没写 —— auditor-246 一口气灌了四个突变全绿，就是这么发现的；改成上面这套之后，
原本五个抓不到的突变全进了。
