# 随时掼掼蛋 · H5 + PWA 方案（修订版）

> 2026-10-13 修订。前提：暂不做微信小程序，先用 H5 + PWA + Web Push 在雅加达跑通。

## 1. 一句话原则

**微信里完成报名；浏览器 / PWA 只负责收提醒；身份靠 token 跨环境交接；分享用海报 + 话术，WhatsApp 用 OG 卡片。**

推送是报名之后的增强，不是报名的前置条件。任何一步都不能要求「先跳出微信」才能占座。

## 2. 运行环境矩阵

| 环境 | 能做什么 | 不能做什么 | 产品处理 |
|---|---|---|---|
| 微信内置浏览器 | 浏览、报名、发起、看详情 | Service Worker / 推送、下载 .ics、自定义分享卡（无 JS-SDK） | 主力落地环境，完整可用；提醒环节引导跳出 |
| Android Chrome（有 GMS） | 全部 + 推送（无需安装） | — | 直接请求通知权限 |
| iOS Safari（16.4+） | 全部 + 下载 .ics | 浏览器内不能推送 | 引导「添加到主屏幕」 |
| iOS 主屏幕 PWA | 全部 + 推送 | 与 Safari **存储隔离** | 首次打开自动认领身份，再请求通知 |
| 国行安卓 / 华为 / 鸿蒙（无 GMS），厂商自带浏览器 | 浏览、报名 | 推送 | 能力检测失败后直接走兜底（日历 / WhatsApp / 群话术），不展示无效的开启按钮 |
| WhatsApp 内置浏览器 | 浏览、报名 | 推送 | 同微信，但分享卡片可用 OG |

能力检测以 `'serviceWorker' in navigator && 'PushManager' in window` 加 UA 判断为准，**不按品牌猜**。

## 3. 核心流程（报名 → 提醒）

```
群里点链接（微信内）
  → 03 牌局详情 → 「报名占座」→ 底部弹层填称呼（首次）→ 报名成功
  → 11 报名成功弹层：「开局前提醒我」
        ├─ 当前环境支持推送（Android Chrome / iOS PWA）→ 直接请求权限
        ├─ 在微信 / WhatsApp 内 → 12 跳出引导（URL 带 claim token）
        │     → Android Chrome：请求权限
        │     → iOS Safari：13 添加到主屏幕引导 → 14 PWA 首开：认领身份 + 请求权限
        └─ 不支持推送 → 加入日历 / 用 WhatsApp 提醒我 / 我自己记得
  → 任何分支都可以「先不用」，报名不受影响
```

关键点：
- 弹层在**报名成功之后**出现，带着具体的局（「周四 19:30 Pacific Place」），这时用户最有动机开提醒。
- 用户选「先不用」后，本局不再弹；03 详情页保留一个轻量「提醒未开启」状态条。

## 4. 身份方案（免注册 + 跨环境交接）

问题：微信内置浏览器、Safari/Chrome、iOS 主屏幕 PWA 三者存储互相隔离，免注册身份会裂成三份。

方案：
1. **匿名用户**：首次填称呼即在服务端创建 `user_id`，前端存长期 `device_token`（cookie + localStorage 双写）。
2. **跳出交接**：生成一次性 `claim_token`（10 分钟有效，单次使用），拼进跳出链接 `?claim=xxx`。新环境打开后用它换取同一个 `user_id`，URL 立即清掉参数。
3. **iOS PWA**：manifest 的 `start_url` 无法动态带 token。做法是在 Safari 里点「添加到主屏幕」前，把 `claim_token` 写入 Safari 的 cookie；PWA 首开时如果没有身份，展示 14 屏「这是你吗？」，让用户输入 6 位认领码（Safari 引导页上显示；只能在签发时的同一网络使用，见 server-design §5.2），兜底保证能认领。
4. **可选绑定**（10「我的」里）：绑定 WhatsApp 号码，用于换手机或清缓存后找回。不强制。
5. **不做用户侧合并**：设备已有别的身份时，兑换 claim 需要用户确认后切换设备（server-design §5.2）；合并只作为 admin 工具保留。

## 5. 分享方案（替代小程序卡片）

微信里的 H5 链接没法渲染成 04 屏那种牌桌卡片，所以分享面板改成四个出口：

| 出口 | 实现 | 适用 |
|---|---|---|
| **保存海报** | 前端 Canvas 生成：时间、地点、座位状态、二维码 | 微信群主力 |
| **复制话术** | 「今天 19:30 Pacific Place 差 1 人，来的点 👉 链接」，随缺人状态实时变化 | 微信群、任意 IM |
| **发到 WhatsApp** | `wa.me/?text=` + 链接；页面配置 OG 标签，牌局页 OG 图由服务端按局动态生成 | WhatsApp 群（有原生卡片） |
| **系统分享** | `navigator.share`（支持时显示） | 浏览器 / PWA 内 |

在微信内置浏览器里长按图片保存可能失败，海报预览要提示「长按图片保存」。

## 6. 提醒方案

| 通道 | 覆盖 | 触发 |
|---|---|---|
| Web Push（VAPID） | Android Chrome、iOS PWA | 成局（4/4）、开局前 1 小时、有人退出导致缺人、局头改时间 |
| .ics / Google Calendar 链接 | 所有跳出到浏览器的用户 | 报名成功、成局 |
| WhatsApp 自提醒 | 不支持推送的用户 | 生成一条带时间地点的消息，发给自己或群 |
| 局头复制回群话术 | 所有人 | 缺人时局头一键复制 |

## 7. 技术栈

> 2026-10-13 变更：放弃 Netlify + Supabase，改用 **Go 单一二进制 + 内嵌 SQLite + 单个 Docker 镜像**。完整设计见 [server-design.md](server-design.md)。

- 前端：Preact + Vite 构建成 H5，加上 Service Worker 和 Web App Manifest，构建产物用 `embed` 打进 Go 二进制。
- 服务端：一个 Go 进程，负责 API、静态页面、`/g/:code` 的 OG 注入、海报和 OG 图渲染、.ics、outbox 定时提醒和 Web Push。
- 数据库：SQLite（WAL 模式），数据文件放在 `/data` 卷；每小时快照，并加密上传异地（上线前必须配置）。
- 部署：雅加达或新加坡的 VPS，`docker run` 一个容器；内置 autocert 签发 HTTPS 证书，主域名和备用域名可以同时配置。

## 8. 指标

| 指标 | 含义 |
|---|---|
| 报名转化率 = 报名数 / 详情页 UV（分环境） | 微信内报名是否顺畅 |
| **提醒开启率 = 成功开启推送或加日历的人 / 报名人数**（分平台） | 身份交接和跳出引导的效果 |
| 身份认领成功率 = 认领成功 / 跳出次数 | claim token 链路是否可靠 |
| 「没看到消息」流失局占比 | 推送 + 兜底能否替代小程序 |

## 9. 风险

- **微信拦截域名**：备用域名（`GUANDAN_DOMAIN` 支持同时配置多个域名）；分享以海报为主，链接为辅。
- **单机部署**：只有一台 VPS，自己负责备份和探活，见 server-design.md §8。
- **iOS 安装漏斗太长**：iOS 的提醒以日历为主，推送为辅，这个预期要提前定好。
- **无 GMS 机型占比高**（华人用户多国行机）：上线第一周统计推送能力检测的失败率，超过 40% 时提高 WhatsApp 兜底的优先级。

## 10. 分期

1. **阶段 1（phase:1）**：微信内报名、身份系统（含 claim）、海报和话术分享、.ics。
2. **阶段 2（phase:2）**：Web Push（Android → iOS PWA）、11–14 引导屏、WhatsApp OG。
3. **阶段 3（phase:3）**：蛋蛋 Agent、牌友关系、学牌。
